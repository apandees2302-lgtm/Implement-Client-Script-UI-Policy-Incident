# Project Testing

## 1. Introduction

Testing is an important phase of the project. It is used to check whether the implemented Client Scripts and UI Policies work correctly in the Incident application.

## 2. Testing Objectives

- To verify the Client Script functionality.
- To verify the UI Policy functionality.
- To check mandatory field validations.
- To verify that the Incident form works correctly.
- To identify and correct errors.

## 3. Test Cases

### Test Case 1: High Impact Incident
When the Impact is set to High, the required fields and related UI Policy conditions are checked.

### Test Case 2: Assignment Group Validation
The Assignment Group field is checked according to the defined UI Policy conditions.

### Test Case 3: Urgency Validation
The Urgency field is automatically controlled based on the Incident Impact.

### Test Case 4: State Change Validation
The Client Script prevents an invalid State change through list editing.

### Test Case 5: User Assignment Validation
The Client Script checks whether the Incident is assigned to a valid user.

## 4. Testing Result

The Client Scripts and UI Policies were tested successfully. The required validations and conditions worked as expected.

## 5. Conclusion

Testing helped to verify the functionality and correctness of the implemented Client Scripts and UI Policies in the Incident application.
