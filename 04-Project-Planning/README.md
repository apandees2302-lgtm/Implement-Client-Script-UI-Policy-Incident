# Phase 4 – Project Planning

## Project Title

Implement Client Script & UI Policy (Incident)

## Platform

ServiceNow

## Module

Incident Management

## 1. Project Plan

The project is planned and implemented in different stages to ensure that all required Incident controls are configured and tested properly.

## 2. Planned Activities

| Activity | Description |
|---|---|
| UI Policy Creation | Create High Impact Control UI Policy |
| UI Policy Action | Configure Urgency as read-only |
| onChange Script | Automatically set Urgency to High |
| onSubmit Script | Validate Assigned To before submission |
| onCellEdit Script | Prevent State changes through list editing |
| Testing | Verify all configured behaviors |
| Documentation | Prepare project documentation |
| Demonstration | Record the complete project demonstration |

## 3. Implementation Sequence

1. Create the UI Policy for High Impact Incidents.
2. Configure the UI Policy Action for Urgency.
3. Create the onChange Client Script.
4. Create the onSubmit Client Script.
5. Create the onCellEdit Client Script.
6. Test each configuration.
7. Record screenshots of successful results.
8. Prepare the final project documentation.
9. Record the project demonstration video.
10. Upload project files to the GitHub repository.

## 4. Team Responsibilities

The project team will divide the work related to configuration, testing, documentation, screenshots, and demonstration among team members.

## 5. Testing Plan

The following scenarios will be tested:

- High Impact Incident
- Automatic Urgency update
- Missing Assigned To validation
- Successful Incident submission
- Reverse UI Policy condition
- State list-edit restriction
- Form-based State update

## 6. Project Deliverables

The planned deliverables are:

- GitHub Public Repository
- Phase-wise project files
- ServiceNow configuration screenshots
- Testing evidence
- Project documentation
- Project demonstration video
- Google Drive demo video link

## 7. Expected Result

The completed project should successfully enforce the required Incident field behavior and validation rules in ServiceNow.

The project should also contain all required documentation and evidence in the GitHub repository.
